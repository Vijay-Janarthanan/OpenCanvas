The official music video behind any song, locked to the song

OpenCanvas finds a song's official music video, checks that it really is the same recording, measures how the two timelines line up, and keeps the picture on the right second — through seeks, skips and the edits a music video makes to its song. It never loops.

These are real screen captures. A screen recorder cannot capture an app's audio, so the soundtrack is the music video's own audio laid in at the position the picture shows; the measured drift between the app's song clock and the picture is in How close the picture stays.

How it works

A music video is rarely the album track with pictures added: it has an intro and often edits — a bar repeated, a bar cut, a longer outro. A single constant offset is right for part of the song and wrong for the rest, so OpenCanvas measures a map: one offset per stretch of the song, and nothing for stretches the video has no scene for.

1 · Song starts
title, artist, the audio's id; the host calls prefetch so the work begins before any screen asks.
2 · Search and rank
structured search results scored on channel (the credited artist's own), "official video", length, verified badge; Shorts, lyric videos, live takes and fan edits fall out.
3 · Stream, two tiers
360p (itag 18) in about 0.2 s so the canvas can start; a 720p+ stream from a second client a moment later replaces it. Both asked for at once.
4 · Verify and map
read the frame-size table of the song's and the candidate's MP4, align the loudness curves, keep the best match — the audio decides which video is real.

Why frame sizes, not audio

An AAC track is a sequence of frames, and each frame's size follows how loud and busy the music is at that instant. The table of sizes sits in the file's header (moov), so reading about 300 KB of each file yields a loudness-like curve for the song and for the video — nothing is downloaded in full and nothing is decoded. The curves (log of the size, minus a 3 s moving average, resampled to 50 Hz) are cross-correlated by FFT in 10 s windows (hop 5 s); a Viterbi pass picks one offset per window and charges for every change of offset, growing with the size of the change — a chorus a minute away is a different place, not an edit. Runs of windows with one offset become segments. The compute takes 12–63 ms.

Why bounded ranges

YouTube throttles an open-ended download of its adaptive streams to about 140 KiB/s — the 18 MiB 720p file takes ~132 s that way — but serves bounded ranges at line rate (1.8 s for the whole file). ProgressiveRangeSource opens with a small first range that doubles up to 4 MiB, and answers a seek with a small range at the new position first (about 106 ms to the first bytes). On Android the host uses 1 MiB chunks through a data source. Playback never waits for a whole file.

Locked to the song, not looping

CanvasSyncPolicy is the whole playback brain, pure Kotlin: inside each segment videoTime = songTime + offset. Every 250 ms (and at once when seekDetected sees the song jump) it answers Nudge (±5 % speed to absorb small drift), SeekTo (drift over 500 ms, or an edit point), Hold, Hidden (no matching picture here — show the cover) or Ended (the song outlasts the video — never loop). Tolerance is 150 ms.

One code path everywhere

The search, ranking, stream resolution, verification, alignment, cache and policy are one shared Kotlin source set used by Android and the desktop JVM — there is no per-platform sync and no daemon. A measured map is stored per (song, video) pair, so the next play needs no measuring (0–25 ms); sessions are shared, so a UI that restarts its request finds the work its predecessor started.

Quickstart

Not tied to any app: you need the song's title and artist, and the id of the audio you are playing (or a place its audio can be read).

1. Add the dependency

repositories {
    mavenCentral()
    maven { url = uri("https://jitpack.io") }
}
dependencies {
    implementation("com.github.Vijay-Janarthanan:OpenCanvas:1.0.0")
    implementation("com.github.Vijay-Janarthanan.OpenCanvas:opencanvas-compose:1.0.0") // optional

2. Configure once, at app start

OpenCanvas.configure(
    OpenCanvasConfig(
        cacheDirectory = File(context.filesDir, "opencanvas"), // measured maps live here
        log = { Log.d("OpenCanvas", it) },                     // one line per stage, with timings
    ),
)

3. Start when the track starts, show when a screen asks

// when the song starts (returns at once; the work runs on the library's own scope)
OpenCanvas.prefetch(
    title = "Blinding Lights", artist = "The Weeknd", durationSec = 200,
    mode = OpenCanvasMode.FULL_SYNCED_VIDEO,
    resolution = OpenCanvasResolution.HD_720P,
    trackVideoId = "fHI8X4OXluQ",        // YouTube (Music) id of the audio you are playing
)

// in the screen that shows the video
OpenCanvas.resolveFlow(
    title = "Blinding Lights", artist = "The Weeknd", durationSec = 200,
    mode = OpenCanvasMode.FULL_SYNCED_VIDEO,
    resolution = OpenCanvasResolution.HD_720P,
    trackVideoId = "fHI8X4OXluQ",
).collect { track ->
    when (track.syncStage) {
        SyncStage.PENDING  -> player.prepare(track.videoStreamUrl, track.videoHeaders) // buffer, don't show yet
        SyncStage.MEASURED -> { policy = CanvasSyncPolicy(track.syncMap(), track.videoDurationMs); showVideo() }
        SyncStage.NONE     -> showStillArtwork()   // no video lines up with this song
    }
}

The flow emits when the stream is known (PENDING), when the map is ready (MEASURED) and again if a taller stream arrives. Collectors of one request share one measurement; abandon the flow and the work is dropped after a short grace. resolve(...) is the one-shot version.

4. Keep the video on the song

// every 250 ms, and at once when policy.seekDetected(...) is true or the track changes
when (val action = policy.decide(songMs, video.positionMs, songPlaying, video.isReady)) {
    Hidden    -> showStillArtwork()            // no matching picture in this stretch of the song
    Hold      -> Unit
    Ended     -> showStillArtwork()            // the song outlasts the video: never loop
    is SeekTo -> video.seekTo(action.videoMs)
    is Nudge  -> video.setSpeed(action.speed)  // at most ±5 %, imperceptible
}

The policy contains no player: use ExoPlayer, VLC, Skiko — anything that reports a position and seeks. On a track change, build a new policy from the new track.

Songs that are not on YouTube

OpenCanvas.resolveFlow(
    title, artist,
    songAudio = SongAudio.Stream(File("/music/song.m4a")),
    mode = OpenCanvasMode.FULL_SYNCED_VIDEO,
)

Any http(s) URL that honours range requests, or a file, works: the audio is read once.

Limits you should know

  • It rides on YouTube's undocumented player endpoints, the ones its own apps use. They can change; backends are pluggable for that reason, but today's defaults may one day need an update. Check YouTube's Terms of Service for your use case.
  • A different mix, a live cut or a cover has no map, so it gets no canvas (the still cover stays) instead of a wrong one. A heavily edited video is aligned piecewise and unmatched stretches are hidden.
  • In BitChord a synced music video wins over a label's short loop (Apple, Tidal, Spotify, community); the label sources are only the fallback for songs without a video that lines up.
  • Measured on an emulator and a desktop, not on phones. 720p decode cost and battery are not measured.
  • Maps are measured from the audio as your player plays it: pass the id that matches the master you play (or songAudio).
